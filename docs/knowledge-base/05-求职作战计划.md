## 核心原则：面试题驱动 + 强制输出

```
❌ 旧模式：看视频 → 看论文 → 看文档 → "学到了" → 面试一问就卡
✅ 新模式：抽一道面试题 → 尝试回答 → 发现不会 → 定向学 → 写出答案 → 说出答案
```

**铁律：每 1 小时输入，至少 1 小时输出。输入输出比 ≥ 1:1。**

输出形式（按难度递增）：
1. 写面试答案（文字稿）→ 最基础，每天必须做
2. 录口头回答（2 分钟）→ 回听找卡顿点
3. 写到项目里（可运行的代码）→ 最扎实，能堵住追问
4. 发博客/动态 → 制造人脉信号

## 个人项目：知识落地的载体

learn-claude-code 是学习项目，你还需要一个**展示项目**：把所有学到的东西整合到一个能用的产品里，面试时 5 分钟 demo 比讲 30 分钟有用。你已有的 `resume-editor-agent` 可以作为起点。

### 项目文档体系

```
个人项目/
├── PRD.md                    ← 产品需求文档（为什么做、做什么、不做什么）
├── ARCHITECTURE.md           ← 技术架构决策（为什么选这个方案）
├── ROADMAP.md                ← 迭代路线（按周规划）
├── LEARNING_LOG.md           ← 学习融入记录（下面有模板）
├── OPENSOURCE_STUDY.md       ← 开源项目学习笔记
└── code/                     ← 实际代码
```

### PRD 模板

```markdown
# PRD: {项目名}

## 一句话定位
{用一句话说清这是什么，解决什么问题}

## 目标用户
- {谁会用这个}

## 核心功能（MVP）
1. {功能1}
2. {功能2}
3. {功能3}

## 不做的事（防范围蔓延）
- {明确不做什么}

## 技术选型
- 前端: {React/Next.js/...}
- 后端: {FastAPI/Flask/...}
- AI: {Claude API + MCP + RAG + ...}

## 成功指标
- {怎么判断做成了}
```

### LEARNING_LOG 模板（最关键）

每学一个新东西、研究一个开源项目后**立即记录**，格式固定：

```markdown
## {日期} — {学到的东西}

**来源**: {面试题 / 开源项目 / 论文 / 视频}
**标签**: {沿用 00-标签索引 的标签体系}

### 核心概念（3 句话）
1.
2.
3.

### 怎么融入我的项目
- 改动点: {具体改哪个文件/模块}
- 预期效果: {改完之后能怎样}

### 融入状态
- [ ] 已写入 PRD 或 ROADMAP
- [ ] 已提交代码（commit: xxxxxx）
- [ ] 已归档到面试题库
```

### 开源项目 → 融入流程

```
发现开源项目（GitHub trending / 论文引用 / 面试提到）
  ↓
30min 速读：看 README + 核心文件 + 架构图
  ↓
提取 1 个可复用的点子（不要贪多）
  ↓
写入 LEARNING_LOG
  ↓
当天或第二天写进自己的项目
  ↓
commit 时标注灵感来源
```

**避免**：花 3 天读完源码什么都没写 → 白看。
**正确**：看到 LangGraph 用 checkpointer 做状态持久化 → 当天给自己的项目加一个 checkpoint 机制。

### Vibe Coding 纪律

用 AI 辅助写代码可以，但有三条红线：

1. **AI 写的代码你必须能解释** — 面试官不会问 AI，会问你
2. **架构决策你来做，AI 来执行** — 不要问 AI "怎么做架构"，问"怎么实现这个方案"
3. **每 commit 写一行意图注释** — 你的设计决策是什么，不是 AI 干了什么

```
❌ commit: "AI generated code"
✅ commit: "加 subagent timeout(30s)+partial_result：超时返回已完成部分而非全丢"
```

--- learn-claude-code 之后：学习优先级

> 按「面试出现频率 × 能讲出深度的概率」排序

| 优先级 | 内容 | 为什么 | 输出形式 |
|--------|------|--------|---------|
| **P0** | 项目痛点深化 | 你已有代码基础，最容易出深度 | 写进项目 + 写博客 |
| **P0** | RAG 全链路 | 面试 100% 考，出现频率最高 | 写进项目 + 面试答案 |
| **P1** | Multi-Agent 停止条件 | 你的项目直接踩过坑，故事真实 | 写进项目 + 面试答案 |
| **P1** | Context Engineering | learn-claude-code s06 已覆盖，只需包装 | 面试答案 + 博客 |
| **P1** | MCP 协议 | 2026 最热，大厂高频 | demo 代码 + 面试答案 |
| **P2** | Tool Calling 异常处理 | 字节面试官原题 | 写进项目 + 面试答案 |
| **P2** | 框架对比判断力 | 高级工程师标志 | 跑 demo + 写对比文章 |

### 学习流程（每个主题都这样走）

```
抽题（2min）
  ↓
裸答一遍，录音（5min）          ← 暴露真实水平
  ↓
对照答案 + 查文档补漏（30min）   ← 精准输入
  ↓
写出完整面试答案（20min）        ← 文字输出
  ↓
脱稿讲一遍，录音回听（10min）    ← 口头输出
  ↓
能写代码的写进项目（30min+）     ← 代码输出
  ↓
归档到 Notion（10min）           ← 可检索
```

## 五大模块的具体执行

### 1. 知识储备（面试题驱动）

**每天深度块的使用方式**：

| 时段 | 内容 | 输入/输出 |
|------|------|----------|
| 上午深度块 (2.5h) | 抽题 → 补漏 → 写答案 → 写代码 | 输入 1h / 输出 1.5h |
| 下午深度块 (3h) | 项目开发：把学到的落地 | 几乎全是输出 |
| 归档块 (1h) | 整理答案 + Notion 入库 | 输出 |

**8 周推进节奏**：

| 周次 | P0 主线 | 副线 | 本周输出物 |
|------|---------|------|-----------|
| Week 1 | RAG chunking + 混合检索 | 项目加 timeout/circuit-breaker | 3 道 RAG 面试答案 + 代码 commit |
| Week 2 | RAG Rerank + 评估(RAGAS) | 项目加 subagent partial result | 3 道 RAG 面试答案 + 代码 commit |
| Week 3 | MCP 协议 + 接一个 server | 项目 multi-agent 加停止条件 | 2 道 MCP 答案 + demo 代码 |
| Week 4 | Multi-Agent 停止条件深化 | 项目 A2A 加 cost cap | 博客初稿 + 代码 commit |
| Week 5 | Context Engineering 包装 | LangGraph/CrewAI demo | 2 道 Context 答案 + 框架对比笔记 |
| Week 6 | Tool Calling 异常处理三层 | 简历通用版定稿 | 2 道 Tool Calling 答案 |
| Week 7 | 模拟面试 + 查漏补缺 | 简历定制版 × 5 | 5 份定向简历 |
| Week 8 | 模拟面试 + 投递冲刺 | 博客发布 | 10 份投递 + 1 篇博客 |

**学习方法**：
- ❌ 不要：从头到尾看文档/看视频/看论文，看完再动手
- ✅ 要：先看一道面试题 → 尝试回答 → 发现不知道 Rerank 原理 → 定向搜资料 → 写出答案 → 写代码验证

### 3. 简历编写

**每周三下午** + **有高质量 JD 时触发**

工作流：
1. 拿到 JD → 用 `job-description-analyzer` 分析
2. Gap 分析：标注 真实匹配 / 可重新包装 / 暂不具备
3. 针对 JD 调整：技能区关键词 / 项目经历侧重点
4. 通用简历版本存在 `resume/master-v2.md`
5. 定向版本存在 `resume/tailored/{公司名}-{岗位}.md`

**两版简历策略**：

| 版本 | 用途 | 特点 |
|------|------|------|
| 通用版 | 挂招聘平台、海投 | 聚焦 Agent 深度，基础设施列技能区不展开 |
| 定制版 | 精准投递 | 按 JD 重排项目侧重点 + 补关键词 |

**每周三检查**：通用版是否需要根据本周看的 JD 趋势微调。

## 你漏掉的东西

你提到的"还有啥来着"——以下是补充：

### 6. 投递漏斗管理

光沟通不够，需要跟踪转化率：

```
第1周：投 5 份 → 几个回复？几个面试？
第2周：调整简历 → 再投 5 份
...
目标：每 10 份投递 → 3 个面试 → 1 个 offer
```

如果投了 10 份零回复 → 问题在简历，需要复盘。

### 7. 模拟面试

每周一次，30 分钟：
- 从面试题库随机抽 3 个题
- 用中文讲技术方案，用英文讲关键术语
- 录音回听 → 找到卡住的地方 → 针对性补
- 周末找人 mock（朋友/付费）

### 8. 运动

你现在没提，但每天坐 8 小时 + 高强度脑力会崩：
- 通勤走路 30 分钟 × 2 = 每天 1 小时步行（够了）
- 图书馆坐久了每 1.5 小时站起来走 5 分钟

### 9. 人脉信号

不是海投，是制造"被找到"的信号：
- 脉脉/领英更新动态（每周 1-2 次，发你学的内容或项目进展）
- 技术博客（CSDN/掘金/知乎）发文章
- GitHub 项目保持 commit 活跃
