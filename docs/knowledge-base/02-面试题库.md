## 5. Multi-Agent 协作

**标签**: `interview/multi-agent`

| 难度 | 真题 | 要点 |
|------|------|------|
| 🟢 | 通信模式有哪些？ | 广播 / Hub-Spoke / P2P / 层级 |
| 🟡 | 分歧怎么解决？ | 规则优先 → 投票 → Manager 仲裁 → 人工升级 |
| 🟡 | 多 Agent 的幻觉怎么防？ | 强制引用来源 + 交叉验证（2 个独立 Agent 确认） |
| 🔴 | 什么时候不该用多 Agent？ | 单 Agent 准确率 >45% 时不加；严格顺序依赖任务暴跌 -39%~-70% |
| 🔴 | 多 Agent 停不下来怎么解决？ | 轮次上限 + cost cap + 独立 Evaluator + 结构化完成条件 |

**你的素材**: s09-s11 — A2A 通信、team protocols、自主 idle cycle

## 8. 项目经验

**标签**: `interview/project-story`

### 面试官想听的结构

```
❌ 我用了 X 框架、Y 工具、Z 数据库
✅ 项目要解决什么问题 → 为什么选这个方案 → 
   踩过什么坑 → 怎么改的 → 学到了什么
```

### 高分回答模式（STAR）

| 步骤 | 内容 |
|------|------|
| Situation | 我在做什么项目，要解决什么 |
| Task | 具体挑战是什么 |
| Action | 我做了什么设计决策，为什么 |
| Result | 量化结果或具体教训 |

### 你的项目话术骨架

**项目名**: 从零实现的 Agent Harness 框架
**STAR**:
- S: 学习 AI Agent 架构，发现框架封装太厚看不到原理
- T: 逆向实现 Claude Code 的 12 个核心机制
- A: 手写 agent loop → tool dispatch → subagent 隔离 → context 压缩 → task system → multi-agent 协作
- R: 踩过 subagent 超时、A2A 停不下来等生产级痛点，理解了 Context Engineering 为什么比 Prompt Engineering 更重要
