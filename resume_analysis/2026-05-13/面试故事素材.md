# 面试故事素材 — 同构关系与叙事角度

简历上不写这些，但面试被问到"你理解 Agent 架构吗"时用的。

---

## 1. 异步任务编排 ↔ Agent Tool 并发调度

**简历上的事实：** 在首都在线设计高并发异步任务编排系统，管理 ECS 实例全生命周期。

**面试中展开：**
> 我之前做 ECS 平台时，核心问题是：大量实例创建请求并发进来，怎么异步分发、追踪每个实例的状态、处理失败、保证最终一致。抽象出来就是四个阶段：**异步分发 → 状态追踪 → 结果收集 → 异常兜底**。
>
> 后来做 Agent 的 Tool Calling 调度时发现，底层架构模式完全一样——Agent 决定要调几个 Tool，系统并发分发，追踪每个 Tool 返回结果，收集合并，处理超时或失败的 Tool。只是调度对象从"云主机"变成了"Tool 调用"。

**适合回答的问题：**
- "你怎么理解 Agent Loop？"
- "多个 Tool 同时调用怎么处理？"

---

## 2. 可观测基础设施 ↔ Agent 可观测与评测

**简历上的事实：** 基于 Prometheus + Kafka + ELK 构建全链路可观测管道。

**面试中展开：**
> 我在首都在线搭的可观测体系是监控 ECS 实例的：启动延迟、失败率、资源消耗、异常检测。工具链是 Prometheus 采集指标、Kafka 做事件流、ELK 做日志聚合。
>
> 这套框架直接平移做 Agent 监控毫无问题：指标从"实例启动延迟"换成"首 Token 延迟"，从"CPU 使用率"换成"Token 消耗"，从"宿主机异常"换成"静默失败检测"。管道不变，语义层换一下就行。

**适合回答的问题：**
- "C 端 Agent 怎么监控效果？"
- "怎么发现 Agent 在静默失败？"

---

## 3. RAG Schema Grounding ↔ 跨会话 Memory 系统

**简历上的事实：** 在 Text-to-SQL Agent 中通过 RAG + FAISS 做 Schema 检索作为上下文。

**面试中展开：**
> 我做的 Schema Grounding 本质是：每次查询进来，从 schema 库里召回相关的表结构信息，拼到上下文里让 Agent 参考。这就已经是 Memory 系统的雏形了——从固定库里做相关度检索、拼入 Context。
>
> 跨会话 Memory 无非是把"固定的 schema 库"换成"动态累积的用户历史记录"，把检索 scope 从"当前查询"扩展到"跨会话"。底层逻辑一样，需要多处理的只是记忆的写入时机、巩固策略和召回准确率优化。

**适合回答的问题：**
- "Memory 系统怎么设计？"
- "长对话 Context 怎么管理？"

---

## 4. Tool 安全管控 ↔ Permission Gate

**简历上的事实：** 在 Text-to-SQL Agent 中对危险操作做执行前拦截 + 审计日志。

**面试中展开：**
> 我做的 Text-to-SQL Agent 天然面临一个问题：用户可能会让 Agent 执行 DROP TABLE。所以我在 Tool Calling 前面加了一层过滤——规则引擎匹配 SQL 类型，拦截危险操作，记录审计日志，通知调用方。
>
> 这就是 Permission Gate 的落地形态。如果再往上抽象，就是注入检测 → Deny Rules → Mode 隔离 → Allow Rules → HITL 这条链路。我做了其中的拦截和审计层，理解整个管道的设计逻辑。

**适合回答的问题：**
- "Agent 安全怎么保证？"
- "Tool Calling 怎么防止误操作？"

---

## 5. 多轮 Context 管理 ↔ Hooks 系统

**简历上的事实：** Token 窗口裁剪 + 关键信息持久化 + Workflow 编排。

**面试中展开：**
> 我在 Agent 里管多轮对话时，需要在每次轮转的特定时机插入逻辑：什么时候裁剪历史、什么时候持久化关键信息、什么时候触发下一步 Workflow。
>
> 这些时机其实就是 Hooks 点：pre\_response 时做窗口裁剪，post\_tool\_call 时判断是否要持久化信息，on\_error 时切换降级策略。我当时的实现是硬编码在 Workflow 里的，但抽象出来就是一套 Hooks 机制。

**适合回答的问题：**
- "Hooks 系统怎么设计？"
- "个性化配置怎么做？"

## 使用方式

面试前看一遍，被问到对应问题时不用回忆简历上写了什么，直接用这里的叙事结构：

1. **抛事实**："我之前做过 X……"
2. **说本质**："抽象出来就是 Y……"
3. **连需求**："所以你说的 Z 问题，本质上和 Y 一样，区别在于……"

这三个步骤比你直接说"我做过类似的"有说服力得多。
