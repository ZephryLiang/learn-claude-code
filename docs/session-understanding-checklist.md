# Session 理解检验清单

## 使用方式

学完一个 session 后，按顺序过下面的 5 关。不需要看代码，能过就说明真懂了。
卡住的环节就是你的认知盲区，回去看代码，搞懂后再从头过一遍。

---

## 第 1 关：一句话说清它解决了什么问题

不问"这代码怎么写"，只问"为什么要有它"。

| 问题 | 你的回答 |
|------|---------|
| 没有这个机制之前，Agent 会遇到什么具体困难？ | |
| 这个机制的核心思路（一句话） | |
| 它改变了 Harness 和 LLM 之间的哪条边界？ | |

**过关标准**：能跟一个没看过代码的同行讲清楚"为什么需要这个 session"。

---

## 第 2 关：画出 messages 数组的完整快照

拿一张白纸，不要看代码。

画出一轮典型的 tool_use → tool_result 往返中，`messages` 数组的完整内容：

```
messages[0] user:
  具体 role/content 是什么？

messages[1] assistant:
  具体有几个 block？每个 block 的 type/name/input 是什么？
  （把 input 的 JSON 内容完整写出来）

messages[2] user (tool_result):
  具体有几个 block？每个 block 的 type/tool_use_id/content 是什么？
  （把 content 的字符串内容写出来）
```

**过关标准**：每个字段（role, type, name, input, tool_use_id, content）都能说清它从哪来、到哪去。写完跟代码对照，漏掉任何一个字段就是盲区。

**重复画 3 轮**：不是画一轮，是连续画 3 轮对话的快照，包括：
- 第 1 轮：LLM 创建任务 + 执行第一步
- 第 2 轮：LLM 更新任务状态 + 执行第二步
- 第 3 轮：LLM 标记完成

---

## 第 3 关：空白文件重写核心机制

新建一个空的 `.py` 文件，从零写出这个 session 的核心类和函数。不需要写完整的 agent loop，只写本 session 新增的那部分。

最少必须写出的：
- 核心数据结构（属性 + 方法签名 + 关键校验逻辑）
- 工具定义（input_schema 的完整 JSON）
- dispatch 逻辑（handler 怎么注册、怎么调用）
- agent loop 中本 session 新增的那几行代码

**过关标准**：写出来的代码能跑通，不需要调试。

---

## 第 4 关：回答边界问题和设计决策

### 4.1 边界问题

| 问题 | 你的回答 |
|------|---------|
| 如果 LLM 传了不合法的参数（格式错误/超出约束），会发生什么？谁在兜底？ | |
| 如果 LLM 连续 N 轮不用这个机制，会发生什么？有没有降级策略？ | |
| 如果 LLM 在某一步失败了（工具调用报错），这个机制怎么应对？ | |
| 这个机制的"状态"存在哪里？程序重启后会怎样？ | |

### 4.2 设计决策（为什么这样而不是那样）

| 问题 | 你的回答 |
|------|---------|
| 某个关键参数（阈值/上限/格式）为什么是这个值？改成别的会怎样？ | |
| 这个机制为什么放在 Harness 而不是靠 system prompt？反过来问：为什么不完全放在 Harness 里自动做？ | |
| 是否存在 LLM 和 Harness 抢"控制权"的情况？怎么解决的？ | |
| 有什么是 LLM 自己做不了、必须靠 Harness 兜底的？ | |

**过关标准**：每个"为什么"都能说出 trade-off——不只是"这样好"，而是"如果反过来会出什么问题"。

---

## 第 5 关：改参数预测行为变化

不改代码，先在脑子里推演，然后实际改代码验证。

| 实验 | 你的预测 | 实际结果 | 一致吗？ |
|------|---------|---------|---------|
| 把约束放宽（如阈值翻倍） | | | |
| 把约束收紧（如阈值为 1） | | | |
| 把这个机制完全去掉 | | | |
| 把提醒/兜底机制静默去掉 | | | |
| 给 LLM 一个会触发边缘情况的输入 | | | |

**过关标准**：预测和实际一致。不一致的话，说明你的心智模型有漏洞，回去查代码搞懂为什么。

---

## 总检查清单

每 session 过完后自评（诚实打勾）：

- [ ] 第 1 关：能一句话讲清"为什么要有它"
- [ ] 第 2 关：能不看代码画出 3 轮 messages 快照
- [ ] 第 3 关：能从空白文件写出核心代码且能跑通
- [ ] 第 4 关：每个设计决策都能说出反向选择的后果
- [ ] 第 5 关：改参数后预测全部命中

5 个全勾 → 这个 session 真懂了，面试随便问。
缺了哪关 → 那一关就是你接下来该做的事。
