## P1-1: MCP 协议

**标签**: `gap/mcp-integration` `interview/mcp`

### 核心理解

- [ ] MCP 设计目的：解耦 Agent 与工具，标准化连接协议
- [ ] MCP vs Skills：协议 vs 能力包，连接方式 vs 任务方法
- [ ] MCP vs Function Call：标准化外部工具 vs 模型内生能力

### 动手计划

- [ ] 跑通至少 1 个 MCP server（如 filesystem / web search）
- [ ] 接入到 learn-claude-code 的 agent loop 中
- [ ] 理解 MCP 的局限性（调用后被"遗忘"、无审计）

### 面试话术

> "MCP 解决的是工具集成的标准化问题 — 以前每接一个新工具要写适配代码，MCP 定义了统一的连接协议。但它不解决'调用后发生了什么'的审计问题，生产环境需要额外加 immutable event log。"

## P1-2: Function Call 微调理解

**标签**: `gap/function-call-finetune`

### 不需要真微调，但要能讲清

- [ ] 为什么 Prompt 无法覆盖分支逻辑（缺信息→反问→调用）
- [ ] 为什么 Prompt 无法让模型学习链式调用（工具间依赖关系）
- [ ] 数据工程为什么比模型工程重要（业务逻辑拆解 > 训练技巧）

### 面试话术

> "FC 微调不是训练模型，是训练业务代理。核心难点在决策 — 模型什么时候调用、调用哪个、调用顺序是什么、缺信息时要不要追问。这些是 Prompt 无法稳定表达的。最大的收获是理解数据工程比模型工程更重要。"

## P2-2: 生产加固

**标签**: `gap/production-hardening`

### 需要在项目中加入的机制

- [ ] **Timeout**: subagent 执行时间上限，超时返回 partial result
- [ ] **Circuit Breaker**: 同工具连续失败 N 次 → 强制中断
- [ ] **Cost Cap**: 单次任务 token/金额 硬上限
- [ ] **Immutable Event Log**: 每次 tool call + 结果 记录，可回放
- [ ] **Health Check**: Agent 运行状态可观测（当前轮次/token消耗/任务进度）
